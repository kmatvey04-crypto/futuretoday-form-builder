# Форма

Локальный сервис форм для тестового задания FutureToday. Менеджер собирает и публикует форму, студент отправляет отклик, менеджер читает ответы.

## Запуск

Нужен Node.js **20 или новее** и npm. В корне этого проекта:

```sh
npm install
npm start
```

Откройте **http://localhost:3000/admin**. Дополнительная сборка или настройка не нужна: `npm start` сам собирает интерфейс и запускает сервер.

Другой порт (например, если 3000 занят):

```sh
PORT=3001 npm start
```

Остановка — `Ctrl+C` в терминале. Для первого `npm install` нужен доступ к npm; после установки сервис работает без интернета, внешних API, ключей, облака и отдельной СУБД. Шрифты и ресурсы локальные.

## Как проверить за минуту

1. В `/admin` нажмите «Создать форму», задайте название и вопросы.
2. Выберите тип ответа и обязательность. Варианты списка укажите каждый с новой строки. Порядок меняется стрелками. Справа — живой предпросмотр.
3. «Сохранить» сохраняет черновик. «Опубликовать» сохраняет его и создаёт ссылку. Откройте ссылку в новой вкладке.
4. Заполните форму и нажмите «Отправить». Появится подтверждение сохранения.
5. Вернитесь в редактор → «Ответы». Для обновления ответов заново откройте вкладку или перезагрузите страницу.

Пять типов: строка, большой текст, email, один вариант из списка, согласие. Оригинальное ТЗ не предписывает конкретные типы. Лимит — 30 вопросов; название до 120 символов, описание до 1000, подпись до 200, текстовый ответ до 500 / большой текст до 5000. У списка 2–20 уникальных непустых вариантов до 100 символов.

## Публикация и сохранность

Изменения в редакторе остаются черновиком до «Обновить публикацию». Ссылка стабильна, после обновления вопросы по ней меняются. Если студент отправляет старую открытую версию, сервер просит обновить страницу. Полученные ответы содержат снимок вопросов и номер версии, поэтому дальнейшее редактирование не меняет историю.

Хранилище — `data/store.json`, автоматически создаётся при первом сохранении. Каждый раз записывается временный файл, затем атомарно переименовывается. Файл остаётся после остановки/перезапуска. Для резервной копии остановите приложение и скопируйте `data/store.json`. Реальные ответы и личные данные нельзя добавлять в Git: `data/*.json` уже исключены.

## Тесты

```sh
npm test
npm run test:e2e
```

`npm test` — интеграционные тесты API: полный путь, отдельный черновик, версии, сохранение после перезапуска, неправильные поля/ответы, Origin/Host, предел размера запроса и ошибки JSON. Используются временные данные и свободные порты.

`npm run test:e2e` — Playwright: сборка и отдельный сервер на **3197**, чистое временное хранилище, Chrome. Проверяет пять типов вопросов, публикацию, клиентские ошибки, отправку, просмотр ответа, перезагрузку, редактирование и ширину 390px. Основной сервер не нужен, рабочие данные не затрагиваются. По умолчанию используется установленный Google Chrome. Если Chrome нет, можно установить Chromium штатной командой Playwright и запустить так:

```sh
npx playwright install chromium
PW_CHANNEL=chromium npm run test:e2e
```

Скриншоты тестов попадают в `test-results/screenshots` (исключены из Git). Другой каталог: `EVIDENCE_DIR=/tmp/forms-shots npm run test:e2e`. Проверки выполнены на macOS, Node 22.22.3, Chrome; точный итог — в `QA.md`.

## Устройство

- `src/main.jsx`, `src/style.css` — React-интерфейс, Vite.
- `server.js` — Express API и статические файлы.
- `model.js` — валидация, публикация, JSON-хранилище.
- `test/` — API- и браузерные проверки.
- `AI_LOG.md` — краткий лог фактического использования AI.

## Границы решения

Это небольшой однопроцессный локальный MVP. `/admin` без авторизации по ТЗ. Сервер слушает только `127.0.0.1`; не предназначен для публикации в интернете. Нет экспорта, вложений, аналитики незавершённых форм, удаления форм и защиты от повторной отправки одним студентом. Нет совместного редактирования: при двух открытых редакторах последнее сохранение заменит предыдущий черновик. JSON подходит для небольшого объёма; для большой нагрузки нужны SQLite и пагинация. Не запускайте несколько процессов с одним файлом данных.

В ТЗ сдача — только ссылка на публичный GitHub. Этот проект подготовлен локально; репозиторий и внешняя публикация не создавались.
